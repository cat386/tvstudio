# TV Studio

Среда визуальной разработки текстовых программ на
[tvision-rs](https://github.com/cat386/tvision-rs) — сама написана на
tvision-rs. В духе Turbo Pascal / Delphi: форма рисуется мышью, меню и
команды описываются в модели приложения, код на Rust генерируется, а
поведение пишется во встроенном редакторе; сборка и запуск — из среды.

## Сборка и запуск

Крейт ждёт tvision-rs рядом с собой (`../tvision-rs`):

```
work/
├── tvision-rs/
└── tvstudio/
```

```
cd tvstudio
cargo run --release                  # последний проект или приветствие
cargo run --release -- путь/к/app.tvsp
cargo run --release -- путь/к/каталогу   # проект в каталоге или исходники Rust
```

Если в указанном каталоге нет файла проекта `.tvsp`, но есть `Cargo.toml`,
среда создаёт рядом с ним проект «программа на Rust» (имя — из
`[package] name`, иначе имя каталога; исходники не трогаются), открывает
его и `src/main.rs` (или `src/lib.rs`). Следующий запуск с тем же
каталогом откроет уже этот проект.

Вместо пути можно взять git-зависимость — см. комментарий в `Cargo.toml`.
Работает в Linux, macOS и Windows 10+ (как и tvision-rs). Нужен `cargo`
в `PATH` (или путь к нему в «Настройки → Параметры среды»).

## Как начать

1. **Файл → Новый проект**: тип проекта, имя (= имя пакета Cargo), каталог
   и откуда брать tvision-rs (git или путь; относительный путь — от
   каталога проекта).
2. **Приложение на tvision-rs** — среда создаёт `Cargo.toml`, `src/main.rs`,
   файл проекта `.tvsp`, форму «О программе» и сразу генерирует код —
   проект собирается «из коробки».

   **Программа на Rust** — только `Cargo.toml` без зависимостей,
   `src/main.rs` («Hello, world!») и `.tvsp` с `"kind": "rust"`. Форм,
   модели и генерации кода нет, окна «Компоненты» и «Инспектор» убираются
   с экрана, а дерево проекта занимает весь левый столбец; редактор кода,
   сборка, запуск и LSP — как у любого проекта. Файлы проектов без поля
   `kind` открываются как проекты tvision-rs.
3. **Ctrl+F9** — собрать и запустить. Экран отдаётся программе; после
   выхода из неё нажмите Enter — вы снова в среде.

## Что умеет

**Дизайнер форм.** Окно дизайнера и есть будущий диалог (рамка, заголовок,
цвет, размер), внутри — настоящие виджеты tvision-rs. Мышь: выбор,
Ctrl+щелчок, перетаскивание, размер за уголок `┘`, выделение рамкой,
двойной щелчок — свойства, правая кнопка — контекстное меню. Клавиши:
стрелки / Shift+стрелки, Tab, Ins, Del, Enter, Ctrl+C/X/V/D, Ctrl+Z/Y,
Ctrl+PgUp/PgDn (порядок Tab). Выравнивание, сетка, номера порядка Tab,
отмена без ограничения шагов, буфер обмена (в том числе системный).
**Shift+F9** показывает форму как настоящий диалог и данные, которые он вернул.

**Класс формы** выбирается при создании (Форма → Новая форма) и меняется
в инспекторе (свойство «Класс», пробел переключает):
* `Dialog` — модальный диалог: `forms::имя::run(app, &mut data)` ждёт OK /
  Отмены, Enter — кнопка по умолчанию, Esc — Отмена;
* `Window` — немодальное окно: `forms::имя::open(app, &data)` вставляет его
  на рабочий стол и возвращает id, `forms::имя::read(app, id)` читает
  данные. У окна есть номер (Alt+1…9) и свойство «Растягивается»
  (значки размера и распахивания); кнопка с `cm::CLOSE` закрывает окно,
  остальные команды идут в `ui::handle_command`.

**Компоненты:** текст, метка (со связью), кнопка (с командой), строка
ввода (проверки `picture`/`range`/`filter`/`lookup`, история), флажки,
переключатели, список (столбцы, прокрутка), многострочное поле, поле со
списком, полоса прокрутки, полоса выполнения, **таблица** (`Table`:
столбцы с шириной, строки данных, правка ячеек, номера строк, сетка) и
**дерево** (`TreeView`: узлы с отступами, линии ветвей, флажки).

**Инспектор свойств** — таблица свойств выделенного элемента или формы;
Enter — правка, пробел — да/нет, ошибочные значения не принимаются.
Полный диалог свойств (с многострочным текстом) — Enter в дизайнере.

**Модель приложения** (Проект →): строка меню с подменю любой вложенности,
строка состояния, команды с действиями («ваш код», «открыть форму»,
«сообщение»), заголовок, русские надписи, стартовая форма. Новое имя
команды в пункте меню сразу заводит команду.

**Генерация кода** (перед каждой сборкой и по Проект → Генерировать код):

| Файл | Что в нём |
|------|-----------|
| `src/ui.rs` | `cmd::*`, `menu_bar()`, `status_line()`, `handle_command()`, `setup()`, `startup()` |
| `src/forms/имя.rs` | `ИмяData` (данные формы), `ИмяIds`, `build()`, `run()` |
| `src/main.rs` | создаётся один раз — это ваш файл |

```rust
let mut data = forms::login::LoginData::default();
if forms::login::run(app, &mut data) == cm::OK {
    println!("{} / {}", data.user, data.remember);
}
```

**F12** переключает дизайнер ↔ сгенерированный код формы.

**Редактор кода**: подсветка Rust/TOML/JSON, подсветка строки и столбца
курсора (отключается в параметрах среды), **rustfmt при сохранении**
файлов `.rs` (F2, «Сохранить всё», перед сборкой; учитывается
`rustfmt.toml` и редакция из `Cargo.toml`; при синтаксической ошибке файл
сохраняется как есть, а место ошибки — в окне сообщений), номера строк, пометки
ошибок сборки (● / ▲), Alt+G — к строке, поиск и замена, поиск по всем
файлам проекта, отмена, клавиши WordStar.

**rust-analyzer (LSP)** в редакторе кода — запускается вместе с проектом:
* **дополнение** — Ctrl+Space или само после `.` и `::`; список у
  курсора фильтруется по набору, Enter/Tab вставляет (сниппеты
  разворачиваются), Esc закрывает;
* **переход к определению** — F12, назад — Alt+←;
* **поиск ссылок** — Shift+F12, список в окне сообщений (Enter — к месту);
* **диагностика в реальном времени** — через ~0,3 с после набора: ● / ▲
  на полосе номеров, места подсвечены фоном, сообщение строки под
  курсором — в строке состояния; Поиск → Диагностика LSP — весь список;
* ход индексации — в заголовке окна сообщений; Поиск → Перезапустить сервер LSP.

Сервер ставится командой `rustup component add rust-analyzer`; другую
команду или путь можно задать в Настройки → Параметры среды (там же он
выключается).

**LSP для Cargo.toml (taplo)** — файлы `.toml` (Cargo.toml, rustfmt.toml)
обслуживает второй сервер, [taplo](https://taplo.tamasfe.dev/): проверка
синтаксиса и ключей по мере набора, дополнение разделов и ключей
(Ctrl+Space, само — после `.`), те же пометки ● / ▲ и общий список
диагностик. Установка: `cargo install taplo-cli --locked --features lsp`;
команда по умолчанию — `taplo lsp stdio`, меняется в поле «Сервер TOML»
параметров среды (пустое поле — не запускать). Серверы работают
независимо: если taplo нет или он упал, rust-analyzer продолжает работу.

Клиент — свой (`src/lsp.rs`), без внешних зависимостей:
JSON-RPC через stdin/stdout, позиции в UTF-32 (или UTF-16, если сервер
не умеет), пути с кириллицей и пробелами кодируются в URI.

**Сборка**: Alt+F9 — check, F9 — build, Ctrl+F9 — run, тесты, очистка,
остановка. cargo идёт в фоне, вывод — в окне сообщений; Enter на строке
ошибки или F8 / Shift+F8 — к месту ошибки.

**Прочее**: дерево проекта, недавние проекты, контекстная справка (F1),
подсказки в строке состояния для каждого окна, темы (gruvbox,
классическая, ч/б), вопрос о сохранении при закрытии и выходе.

## Примеры и импорт программ

В каталоге [`examples/`](examples/README.md) — все 23 примера tvision-rs,
каждый как проект TV Studio: меню, строка состояния и команды — в модели,
все диалоги — формы `forms/*.tvf` (25 форм в 13 проектах; hello,
learn_05_dialog и learn_06_form уже строят диалоги из своих форм):

```
cargo run --release -- examples/tvdemo
```

Свою программу на tvision-rs можно взять в проект: **Файл → Импорт
программы…** или из командной строки:

```
cargo run --bin tvs-import -- путь/main.rs КАТАЛОГ ИМЯ [tvision-rs]
cargo run --bin tvs-import -- --examples ../tvision-rs examples
```

Исходники копируются (с модулями `#[path]` и файлами `include_str!`),
строка меню, строка состояния и константы команд переносятся в модель,
а в коде заменяются вызовами `ui::…`. Меню, собранное функциями или в
цикле, и строка состояния из нескольких `StatusDef::range` остаются в коде.

Диалоги из кода — в формы: **Проект → Формы из кода** или
`cargo run --bin tvs-import -- --forms ПРОЕКТ...`. Небольшой интерпретатор
подмножества Rust вычисляет координаты (переменные, арифметику, циклы
`for … in …iter().enumerate()`, простые замыкания), надписи, пункты,
проверки ввода, связи меток, полосы прокрутки, историю и списки строк
ввода. Свои виджеты и элементы внутри условий перечисляются в отчёте.

## Устройство

| Модуль | |
|--------|---|
| `model` | формы, элементы, меню, команды, проект, клавиши |
| `props` | свойства для инспектора и диалога свойств |
| `builder` | живой диалог tvision-rs по модели (для дизайнера и проверки формы) |
| `codegen` | генерация кода |
| `designer` | документ формы (отмена, буфер, выравнивание), холст и окно дизайнера |
| `inspector` | инспектор свойств на `Table` |
| `toolwins` | палитра, дерево проекта, сообщения, разбор вывода cargo |
| `appdesign` | редакторы меню, строки состояния и команд |
| `codeedit`, `highlight` | редактор кода и подсветка |
| `runner` | cargo в фоновом потоке |
| `importer` | импорт программ на tvision-rs (лексер Rust, разбор цепочек `Menu::new()`) |
| `formextract` | диалоги из кода → формы (интерпретатор подмножества Rust) |
| `lsp` | клиент Language Server Protocol (rust-analyzer, taplo) |
| `ide` | меню, строка состояния, обработчик команд среды; `ide/lsp_glue` — LSP в редакторах (`.rs` → rust-analyzer, `.toml` → taplo) |

Файлы проекта (`.tvsp`) и форм (`.tvf`) — TOML: меню, строка состояния и
команды — массивы таблиц `[[app.menu]]`, `[[app.status]]`, `[[app.commands]]`,
элементы формы — `[[controls]]`; удобно читать, править руками и хранить в
git. Чтение и запись — свой модуль `toml` без внешних зависимостей. Файлы
прежних версий (JSON) открываются как раньше и при первом сохранении
переписываются в TOML.

```toml
format = "tvstudio-form"
version = 1
name = "greeting"
title = "Hello, World!"
w = 30
h = 11

[[controls]]
kind = "button"
name = "ok"
text = "Ok"
command = "cm::CANCEL"
```

## Тесты

```
cargo test                                      # 55 тестов, в т.ч. на «невидимом» терминале
cargo test --test codegen_build -- --ignored    # сгенерированный проект со всеми элементами собирается без предупреждений
cargo test --test examples -- --ignored         # все 23 примера собираются и проходят свои тесты
```

Тесты интерфейса проходят полный путь: вставка и перетаскивание
элементов, отмена, инспектор, диалог свойств, редактор меню, новая форма,
F12, а также настоящий `cargo check` с ошибкой, переходом F8 к строке и
пометкой в полосе номеров.

`tests/lsp.rs` проверяет LSP с учебным сервером `tvs-fake-lsp` (тот же
протокол, что у rust-analyzer): диагностику при наборе, список
дополнения, F12 / Alt+← / Shift+F12, перезапуск и сообщение об
отсутствующем сервере, а также второй сервер для Cargo.toml: каждый
файл уходит своему серверу с правильным `languageId`.

## Ограничения

* «Формы из кода» распознают только диалоги (`Dialog::new`); окна
  `Window` из готовых программ пока не извлекаются.
* Свои команды кнопок внутри модального диалога обрабатываются в
  `app.modal_hook` (стандартные OK/Отмена/Да/Нет закрывают диалог сами).
* Отладчика нет — только сборка, запуск и переход к ошибкам.
