# TV Studio

Среда визуальной разработки текстовых программ на
[tvision-rs](https://github.com/cat386/tvision-rs) — сама написана на
tvision-rs. В духе Turbo Pascal / Delphi: форма рисуется мышью, меню и
команды описываются в модели приложения, код на Rust генерируется, а
поведение пишется во встроенном редакторе; сборка и запуск — из среды.

## Сборка и запуск

[![CI](https://github.com/cat386/tvstudio/actions/workflows/ci.yml/badge.svg)](https://github.com/cat386/tvstudio/actions/workflows/ci.yml)
— сборка, тесты, clippy и rustfmt на Ubuntu и Windows при каждом коммите
(`.github/workflows/ci.yml`).

Для сборки TVStudio нужны Rust и Cargo. Зависимость tvision-rs указана
в `Cargo.toml` как Git-зависимость; её ревизия закреплена в `Cargo.lock`.
Соседний каталог `../tvision-rs` для обычного запуска TVStudio не требуется.

Из каталога репозитория:

```sh
cargo build --locked --release --bin tvstudio
cargo run --locked --release --bin tvstudio
cargo run --locked --release --bin tvstudio -- путь/к/app.tvsp
cargo run --locked --release --bin tvstudio -- путь/к/каталогу
```

Указывайте `--bin tvstudio`: репозиторий содержит также служебные
бинарники, поэтому простой `cargo run` может потребовать выбрать цель.
При первой сборке Cargo нужен доступ к зависимостям.

Для примеров и тестов, использующих локальный путь, нужна соседняя копия:

```text
work/
├── tvision-rs/
└── tvstudio/
```

В текущем CI соседняя копия tvision-rs закреплена на ревизии
`74a4365a2236e8d74abb69c717aa3ef00ff32263`. Подготовить её можно из
каталога TVStudio, если `../tvision-rs` ещё не существует:

```sh
git clone https://github.com/cat386/tvision-rs ../tvision-rs
git -C ../tvision-rs checkout 74a4365a2236e8d74abb69c717aa3ef00ff32263
```

Если в указанном каталоге нет файла проекта `.tvsp`, но есть `Cargo.toml`,
среда создаёт рядом с ним проект «программа на Rust» (имя — из
`[package] name`, иначе имя каталога; исходники не трогаются), открывает
его и `src/main.rs` (или `src/lib.rs`). Следующий запуск с тем же
каталогом откроет уже этот проект.

**Workspace.** Участники из `[workspace] members` (с шаблонами вроде
`crates/*`, без `exclude`) показываются в дереве проекта отдельными узлами
◇ с именем пакета — у каждого `src`, `tests`, `examples`, `benches`,
`build.rs` (что есть) и свой `Cargo.toml`; у корневого пакета — так же.
Если в корне нет своего пакета, открывается `main.rs` / `lib.rs` первого
участника. Сборка (F9) — всего workspace; запуск (Ctrl+F9) —
`cargo run -p` того участника, в котором файл верхнего окна редактора (если
у него есть программа), иначе корневого пакета или первого участника с
программой.

Работает в Linux, macOS и Windows 10+ (как и tvision-rs). Нужен `cargo`
в `PATH` (или путь к нему в «Файл → Параметры среды»).

## Интерфейс и клавиши

Без проекта открывается стартовая панель: новый проект, открытие,
клонирование и недавние проекты. Параметры среды находятся в меню
**Файл → Параметры среды**: четыре раздела переключаются кнопками
или Ctrl+PgUp / Ctrl+PgDn. Окно параметров среды имеет размер 90×22;
для его полного отображения используйте терминал не уже 90 колонок
и высотой от 25 строк. Для работы с несколькими окнами удобнее 120×40.
Длинные свойства компонентов разбиты на страницы; кнопки применения
и отмены остаются видимыми. Флажки переключаются пробелом, варианты
класса/цвета выбираются из списка. В инспекторе Enter открывает выбор
известного значения; F2 и набор текста сохраняют ручное редактирование.

**Код** объединяет поиск, переходы и функции серверов языка.
**Проект → Git** открывает операции репозитория.
Alt+F3 закрывает окно; Ctrl+H открывает замену. В дизайнере
Del удаляет компоненты, Ctrl+D дублирует, Shift+F9 открывает
предпросмотр формы. Ctrl+F9 запускает приложение. Таблица клавиш
в справке формируется из тех же определений, что и меню.

## Как начать

1. **Файл → Новый проект**: тип проекта, имя (= имя пакета Cargo), каталог
   и откуда брать tvision-rs (git или путь; относительный путь — от
   каталога проекта).
2. **Приложение на tvision-rs** — среда создаёт `Cargo.toml`, `src/main.rs`,
   файл проекта `.tvsp`, форму «О программе» и сразу генерирует код —
   проект собирается «из коробки».

   **Программа на Rust** — только `Cargo.toml` без зависимостей,
   `src/main.rs` («Hello, world!») и `.tvsp` с `kind: rust`. Форм,
   модели и генерации кода нет, окно «Инспектор» (компоненты и свойства)
   убирается с экрана, дерево проекта встаёт к правому краю, а редактор
   занимает место от левого края до него; редактор кода,
   сборка, запуск и LSP — как у любого проекта. Файлы проектов без поля
   `kind` открываются как проекты tvision-rs.
3. **Ctrl+F9** — собрать и запустить. Экран отдаётся программе; после
   выхода из неё нажмите Enter — вы снова в среде.

**Руководство пользователя:** [`docs/guide.md`](docs/guide.md) — запуск,
проверяемые сценарии, редактор, LSP, Git, настройки и учебный проект «Склад».
[PDF от 27 ноября 2026](docs/guide.pdf) — свёрстанная версия актуального
руководства: 27 страниц, кликабельное оглавление и закладки. Исходник — Markdown.

## Что умеет

**Дизайнер форм.** Окно дизайнера и есть будущий диалог (рамка, заголовок,
цвет, размер), внутри — настоящие виджеты tvision-rs. Мышь: выбор,
Ctrl+щелчок, перетаскивание, размер за уголок `┘`, выделение рамкой,
двойной щелчок — свойства, правая кнопка — контекстное меню. Клавиши:
стрелки / Shift+стрелки, Tab, Ins, Del, Enter, Ctrl+C/X/V/D, Ctrl+Z (отмена), Ctrl+Y (повтор в дизайнере),
Ctrl+PgUp/PgDn (порядок Tab). Выравнивание, сетка, номера порядка Tab,
отмена без ограничения шагов, буфер обмена (в том числе системный).
**Shift+F9** показывает форму как настоящий диалог и данные, которые он вернул.
Общие команды «Правка → Повторить» используют Ctrl+Shift+Z; локальное
Ctrl+Y в дизайнере также выполняет повтор, а в редакторе удаляет строку.

**Класс формы** выбирается при создании (Форма → Новая форма) и меняется
в инспекторе (свойство «Класс»: Enter открывает список вариантов):
* `Dialog` — модальный диалог: `forms::имя::run(app, &mut data)` ждёт OK /
  Отмены, Enter — кнопка по умолчанию, Esc — Отмена;
* `Window` — немодальное окно: `forms::имя::open(app, &data)` вставляет его
  на рабочий стол и возвращает id, `forms::имя::read(app, id)` читает
  данные. У окна есть номер (Alt+1…9) и свойство «Растягивается»
  (значки размера и разворачивания); кнопка с `cm::CLOSE` закрывает окно,
  остальные команды идут в `ui::handle_command`.

**Компоненты:** текст, метка (со связью), кнопка (с командой), строка
ввода (проверки `picture`/`range`/`filter`/`lookup`, история), флажки,
переключатели, список (столбцы, прокрутка), многострочное поле, поле со
списком, полоса прокрутки, полоса выполнения, **таблица** (`Table`:
столбцы с шириной, строки данных, правка ячеек, номера строк, сетка),
**дерево** (`TreeView`: узлы с отступами, линии ветвей, флажки) и
**линия-разделитель** (`Line`: горизонтальная или вертикальная, одинарная
или двойная, «до рамки» — концы соединяются с рамкой окна, пересечения
линий рисуются как `┼`).

**Раскладка окон**: слева — формы и редакторы кода, у правого края —
дерево проекта (сверху) и под ним инспектор, внизу — сообщения.

**Инспектор** — одно окно у правого края, под деревом проекта: сверху компоненты (Enter или
двойной щелчок добавляет элемент на форму), под ними таблица свойств
выделенного элемента или формы; Tab переходит между ними, «Окно →
Компоненты» ведёт к списку, F11 — к свойствам (повторно — назад в
дизайнер). Enter — правка, пробел — да/нет, ошибочные значения не принимаются.
Полный диалог свойств (с многострочным текстом) — Enter в дизайнере.

**Модель приложения** (Проект →): строка меню с подменю любой вложенности,
строка состояния, команды с действиями («ваш код», «открыть форму»,
«сообщение»), заголовок, русские надписи, стартовая форма. Новое имя
команды в пункте меню сразу заводит команду.

**Генерация кода** (перед каждой сборкой и по Проект → Генерировать код):

| Файл | Что в нём |
|------|-----------|
| `src/ui.rs` | `cmd::*`, `menu_bar()`, `status_line()`, `handle_command()`, `setup()`, `startup()` |
| `src/forms/имя.rs` | `ИмяData` (данные формы), `ИмяIds`, `build()`, `run()` |
| `src/main.rs` | создаётся один раз — это ваш файл |

```rust
let mut data = forms::login::LoginData::default();
if forms::login::run(app, &mut data) == cm::OK {
    println!("{} / {}", data.user, data.remember);
}
```

**F12** в дизайнере открывает сгенерированный код формы. В редакторе
F12 означает «К определению» через LSP. Вернуться к форме можно через
дерево проекта или переключение окон (F6 / Shift+F6).

**Редактор кода**: подсветка Rust/TOML/YAML/JSON, подсветка строки и столбца
курсора (отключается в параметрах среды), **rustfmt при сохранении**
файлов `.rs` (F2, «Сохранить всё», перед сборкой; учитывается
`rustfmt.toml` и редакция из `Cargo.toml`; при синтаксической ошибке файл
сохраняется как есть, а место ошибки — в окне сообщений), номера строк, пометки
ошибок сборки (● / ▲), Alt+G — к строке, поиск и замена, поиск по всем
файлам проекта, отмена, клавиши WordStar. **Скобки и кавычки закрываются
сами**: `(` `[` `{` `"` вставляют пару (перед словом, в строке и
комментарии — нет; `r"…"` и `b"…"` — да), закрывающая перешагивает
вставленную, Backspace в пустой паре удаляет обе, Enter в `{}` разносит по
строкам, выделение оборачивается; выключается флажком «Закрывать скобки и
кавычки» в параметрах среды. Курсор остаётся внутри созданной пары.
Одинарная кавычка автоматически не закрывается. Ctrl+V, Shift+Insert
и «Правка → Вставить» добавляют текст без автопар и дополнения.
Вставка средствами терминала может поступать как отдельные нажатия;
для буквальной вставки используйте команду студии.

**rust-analyzer (LSP)** в редакторе кода — запускается вместе с проектом,
если серверы включены и программа установлена:
* **дополнение** — Ctrl+Space или само после `.` и `::`; список у
  курсора фильтруется по набору, Enter/Tab вставляет (сниппеты
  разворачиваются), Esc закрывает;
* **подсказки при наборе** — в файлах `.rs` список открывается сам после
  двух букв имени (не в строках и комментариях): подключённые крейты,
  модули и элементы проекта, а также ещё не подключённые элементы других
  крейтов — при выборе среда сама дописывает `use` (догружая правку через
  `completionItem/resolve`, курсор остаётся у слова); неполный список
  (`isIncomplete`) запрашивается заново с каждой буквой. В само открывшемся
  списке Enter — перевод строки, пока вариант не выбран стрелками (выбор —
  Tab), и показываются только варианты, начинающиеся с набранного. Без
  сервера — словарь проекта (`src/words.rs`): имена из файлов `.rs`, модули
  и крейты из `Cargo.toml`. Флажок «Подсказки при наборе» в параметрах среды;
* **подсказка при наведении (LSP Hover)** — остановите мышь на имени
  переменной, функции или типа: через 400 мс отправляется запрос серверу,
  ответ показывается в рамке внутри редактора. Сигнатура, тип и документация
  зависят от ответа сервера. Над пробелами, пустыми строками, за концом строки
  и вне редактора подсказка скрывается; набор, щелчок и прокрутка также её
  убирают. Она не получает фокус. Пустые и устаревшие ответы не показываются.
  Нужен сервер с поддержкой Hover и терминал, передающий движение мыши;
* **переход к определению** — F12, назад — Alt+←;
* **поиск ссылок** — Shift+F12, список в окне сообщений (Enter — к месту);
* **быстрые исправления** — Alt+Enter (или Ctrl+.): список действий сервера
  для места под курсором («добавить use», «заполнить match»…), выбранная
  правка применяется в редакторе (файлы, которых она касается, открываются);
* **диагностика в реальном времени** — через ~0,3 с после набора: ● / ▲
  на полосе номеров, места подсвечены фоном, сообщение строки под
  курсором — в строке состояния; Код → Серверы языка → Диагностика — весь список;
* ход индексации — в заголовке окна сообщений; Код → Серверы языка → Перезапустить серверы.

Сервер ставится командой `rustup component add rust-analyzer`; другую
команду или путь можно задать в Файл → Параметры среды (там же он
выключается).

Путь с пробелами можно указать целиком; если нужны аргументы, заключите
путь и аргументы с пробелами в кавычки, например:
`"C:\Program Files\Rust\rust-analyzer.exe" --log-file "C:\My Logs\ra.log"`.
Если сервер перестаёт читать сообщения и очередь отправки заполняется,
среда сообщает об ошибке и останавливает сервер; его можно перезапустить
через меню Код → Серверы языка → Перезапустить серверы.

**LSP для Cargo.toml (crates-lsp)** — файлы `.toml` обслуживает второй
сервер, [crates-lsp](https://github.com/MathiasPius/crates-lsp): в
`Cargo.toml` он дополняет версии и features зависимостей (Ctrl+Space,
само — после `serde = "` и после `.`), ставит в конце строки зависимости
серую подсказку (`✓` — версия последняя, `❌ 1.0.210` — есть новее) и
помечает устаревшие и несуществующие версии теми же ● / ▲, они же — в
общем списке диагностик.
Установка: `cargo install --locked crates-lsp`; команда (или полный путь)
меняется в поле «Сервер TOML» раздела «Серверы» параметров среды, пустое поле — не
запускать; прежний сервер taplo, если он остался в настройках, при
запуске заменяется на crates-lsp. Серверы работают независимо: если crates-lsp нет или он упал,
rust-analyzer продолжает работу. Версии crates-lsp берёт с crates.io —
нужна сеть.

Клиент — свой (`src/lsp.rs`), без внешних зависимостей:
JSON-RPC через stdin/stdout, позиции в UTF-32 (или UTF-16, если сервер
не умеет), пути с кириллицей и пробелами кодируются в URI.

**Сборка**: Alt+F9 — check, F9 — build, Ctrl+F9 — run, тесты, очистка,
остановка. **Параметры сборки** (меню Сборка) — профиль Debug / Release
или свой, features, `--target`, пакет workspace, свои аргументы cargo и
аргументы программы; хранятся в проекте (раздел `build`) и используются командами сборки. Для очистки учитываются профиль,
платформа и пакет; features и дополнительные аргументы не передаются
в cargo clean. cargo идёт в фоне, вывод — в окне сообщений; Enter на строке
ошибки или F8 / Shift+F8 — к месту ошибки. Окно **«Ошибки и
предупреждения»** (Ctrl+F8, меню Сборка) — все замечания сборки и
сервера LSP одним списком: сначала ошибки, флажки-фильтры, счётчики в
заголовке, Enter — к месту.

**Прочее**: дерево проекта, недавние проекты, контекстная справка (F1),
подсказки в строке состояния для каждого окна, темы (gruvbox,
классическая, ч/б), вопрос о сохранении при закрытии и выходе.

## Примеры и импорт программ

В каталоге [`examples/`](examples/README.md) — все 23 примера tvision-rs,
каждый как проект TV Studio: меню, строка состояния и команды — в модели,
все диалоги — формы `forms/*.tvf` (25 форм в 13 проектах; hello,
learn_05_dialog и learn_06_form уже строят диалоги из своих форм):

```
cargo run --locked --release --bin tvstudio -- examples/tvdemo
```

Свою программу на tvision-rs можно взять в проект: **Файл → Импорт
программы…** или из командной строки:

```
cargo run --bin tvs-import -- путь/main.rs КАТАЛОГ ИМЯ [tvision-rs]
cargo run --bin tvs-import -- --examples ../tvision-rs examples
```

Исходники копируются (с модулями `#[path]` и файлами `include_str!`),
строка меню, строка состояния и константы команд переносятся в модель,
а в коде заменяются вызовами `ui::…`. Меню, собранное функциями или в
цикле, и строка состояния из нескольких `StatusDef::range` остаются в коде.

Диалоги из кода — в формы: **Проект → Формы из кода** или
`cargo run --bin tvs-import -- --forms ПРОЕКТ...`. Небольшой интерпретатор
подмножества Rust вычисляет координаты (переменные, арифметику, циклы
`for … in …iter().enumerate()`, простые замыкания), надписи, пункты,
проверки ввода, связи меток, полосы прокрутки, историю и списки строк
ввода. Свои виджеты и элементы внутри условий перечисляются в отчёте.

## Устройство

| Модуль | |
|--------|---|
| `model` | формы, элементы, меню, команды, проект, клавиши |
| `props` | свойства для инспектора и диалога свойств |
| `builder` | живой диалог tvision-rs по модели (для дизайнера и проверки формы) |
| `codegen` | генерация кода |
| `designer` | документ формы (отмена, буфер, выравнивание), холст и окно дизайнера |
| `inspector` | окно «Инспектор»: компоненты (список) и свойства (`Table`) |
| `toolwins` | дерево проекта, сообщения, значки компонентов, разбор вывода cargo |
| `appdesign` | редакторы меню, строки состояния и команд |
| `codeedit`, `highlight` | редактор кода и подсветка |
| `runner` | cargo в фоновом потоке |
| `importer` | импорт программ на tvision-rs (лексер Rust, разбор цепочек `Menu::new()`) |
| `formextract` | диалоги из кода → формы (интерпретатор подмножества Rust) |
| `lsp` | клиент Language Server Protocol (rust-analyzer, crates-lsp) |
| `words` | словарь проекта для подсказок без сервера LSP |
| `ide` | меню, строка состояния, обработчик команд среды; `ide/lsp_glue` — LSP в редакторах (`.rs` → rust-analyzer, `.toml` → crates-lsp) |

Файлы проекта (`.tvsp`) и форм (`.tvf`) — YAML: меню, строка состояния и
команды — списки `app.menu`, `app.status`, `app.commands`, элементы формы —
список `controls`; удобно читать, править руками и хранить в git. Чтение и
запись — свой модуль `yaml` без внешних зависимостей (блочный стиль,
строки в кавычках только там, где без них значение прочиталось бы иначе;
файлы читаются и сторонними библиотеками YAML). Файлы прежних версий
(TOML и JSON) открываются как раньше и при первом сохранении
переписываются в YAML.

```yaml
format: tvstudio-form
version: 1
name: greeting
title: Hello, World!
w: 30
h: 11
controls:
  - kind: button
    name: ok
    text: Ok
    command: cm::CANCEL
```

## Тесты

```
cargo test --locked                             # в том числе тесты на HeadlessBackend
cargo test --locked --test codegen_build -- --ignored    # сгенерированный проект со всеми элементами собирается без предупреждений
cargo test --locked --test examples -- --ignored         # все 23 примера собираются и проходят свои тесты
```

Тесты интерфейса проходят полный путь: вставка и перетаскивание
элементов, отмена, инспектор, диалог свойств, редактор меню, новая форма,
F12, а также настоящий `cargo check` с ошибкой, переходом F8 к строке и
пометкой в полосе номеров.

`tests/lsp.rs` проверяет LSP с учебным сервером `tvs-fake-lsp` (тот же
протокол, что у rust-analyzer): диагностику при наборе, список
дополнения, F12 / Alt+← / Shift+F12, перезапуск и сообщение об
отсутствующем сервере, а также второй сервер для Cargo.toml: каждый
файл уходит своему серверу с правильным `languageId`, подсказки в тексте
(в том числе по просьбе сервера `workspace/inlayHint/refresh`) и быстрые
исправления обеих форм правок (`changes` и `documentChanges`).

## Ограничения

* «Формы из кода» понимает `Dialog::new` / `Dialog::centered` и
  `Window::new`; окна своих типов (`TodoWindow` и т.п.) по-прежнему не извлекаются.
* Свои команды кнопок внутри модального диалога обрабатываются в
  `app.modal_hook` (стандартные OK/Отмена/Да/Нет закрывают диалог сами).
* Отладчика нет — только сборка, запуск и переход к ошибкам.

## Git в TV Studio

Подменю **Проект → Git** использует системный `git`. Ниже все пути к Git-командам начинаются с меню «Проект». Если программа не находится в PATH, выберите **Проект → Git → Путь к Git** и введите полный путь к исполняемому файлу. TV Studio проверит версию и запомнит путь. В том же меню можно записать имя и email для текущего репозитория или глобально. Для HTTPS используются настроенные Git credential helpers, для SSH — настройки и агент SSH.

1. Откройте проект и выберите **Проект → Git → Создать репозиторий** либо **Файл → Клонировать репозиторий**. В диалоге введите адрес и укажите родительский каталог вручную или кнопкой **…**. TV Studio создаст в нём папку с именем репозитория. Оставьте поле «Ветка» пустым для ветки по умолчанию или введите имя вручную. Кнопка **Клонировать** сразу запускает клонирование. Кнопка **Список веток…** отдельно запрашивает ветки сервера. Запрос списка завершается ошибкой после 20 секунд без вывода Git, клонирование — после 60 секунд без вывода. IDE откроет найденный в корне `.tvsp` или импортирует Cargo-проект. Для произвольного репозитория откроется окно Git.
2. Выберите **Проект → Git → Изменения**. В заголовке окна видны ветка, отслеживаемая ветка и числа файлов. Две колонки состояния показывают индекс и рабочее дерево: `??` — новый файл, `A.` — подготовленный новый файл, `.M` — изменение на диске, `MM` — изменения есть в обоих местах.
3. **Изменения** показывает рабочее дерево, **Изменения индекса** — подготовленные изменения. Кнопки **+ В индекс** и **− Из индекса** работают с выбранным файлом целиком. **Коммит** записывает содержимое индекса. Сохраните код и формы перед подготовкой файлов. Кнопка **Обновить** перечитывает состояние после сохранения и внешних команд Git.
4. **Добавить origin** подключает существующий удалённый репозиторий. **Получить ссылки (fetch)** получает ссылки origin, **Отправить ветку (push)** отправляет текущую ветку в origin и настраивает upstream. Команды выполняются в фоне. Начало, результат и ошибки отображаются в окне «Сообщения».

5. **Выбрать ветку** показывает локальные и известные удалённые ветки. Текущая отмечена звёздочкой. Выбор удалённой ветки создаёт одноимённую локальную с отслеживанием. **Новая ветка** создаёт ветку от текущего HEAD и сразу переключается на неё.
6. **Обновить ветку (pull)** (`--ff-only`) получает изменения отслеживаемой ветки и переносит HEAD только вперёд. Если ветки разошлись, Git оставляет локальные коммиты и сообщает об ошибке. При успешном переключении или pull IDE перечитывает открытые файлы и формы, затронутые операцией. Перед такими операциями сохраните несохранённые документы.
7. **История коммитов** показывает до 100 коммитов текущей ветки. Выберите запись для просмотра сообщения, автора и diff.

Окно учитывает сохранённое состояние файлов на диске. Выборочная подготовка
отдельных блоков diff — кнопка «Блоки»; merge, rebase и разрешение
конфликтов в интерфейсе пока не реализованы.

### Диалоги и навигация

Длинные свойства сгруппированы по смыслу: «Основное», «Данные»,
«Поведение». Выбранный раздел отмечен точкой; Ctrl+PgUp/PgDn
переключает разделы. «Сохранить» записывает изменения и закрывает
диалог. Во вложенных редакторах меню, строки состояния и команд
ошибка отображается в открытом диалоге, сохраняя введённые поля.

На стартовом экране в недавних проектах сначала показано имя,
затем сокращённый путь. F4 открывает полный путь с горизонтальной
прокруткой. Панель Git располагается над сообщениями; статусы
различают индекс, рабочие изменения и конфликты.
