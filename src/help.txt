.topic Nocontext=0
 TV Studio ▄
  ▀▀▀▀▀▀▀▀▀
TV Studio — среда визуальной разработки текстовых программ на
библиотеке tvision-rs (Turbo Vision для Rust). Форма рисуется мышью,
меню и команды описываются в модели приложения, а код на Rust
генерируется автоматически; поведение пишется в обычном редакторе.

 Разделы
  {Как начать:Start}
  {Дизайнер форм:Designer}
  {Инспектор свойств:Inspector}
  {Компоненты:Palette}
  {Модель приложения:AppModel}
  {Какой код генерируется:Codegen}
  {Редактор кода:Editor}
  {Сборка и запуск:Build}
  {Дерево проекта:ProjectTree}
  {Окно сообщений:Messages}
  {Клавиши:Keys}

Esc — закрыть справку. Tab — к следующей ссылке, Enter — перейти.

.topic Start
 Как начать ▄
  ▀▀▀▀▀▀▀▀▀▀
1. Файл → Новый проект. Выберите тип проекта, укажите имя (оно же
имя пакета Cargo), каталог и откуда брать tvision-rs: из git или с
диска.

2. Приложение на tvision-rs: среда создаст каталог проекта —
Cargo.toml, src/main.rs, файл проекта .tvsp и форму «О программе», —
и откроет форму в {дизайнере:Designer}.

   Программа на Rust: только Cargo.toml (без зависимостей), src/main.rs
и файл проекта. Форм и модели у такого проекта нет, код не
генерируется, окна «Инспектор» (компоненты и свойства) на экране
нет: дерево проекта стоит у правого края, редактор кода — слева от
него. Сборка и сервер LSP работают как обычно.

3. Нажмите Ctrl+F9: проект соберётся и запустится. Меню «Файл → О
программе» покажет вашу форму. После выхода из программы среда
вернётся.

Файл проекта .tvsp и формы .tvf — текст в формате TOML: их можно
открыть в редакторе кода и хранить в git. Файлы старых версий (JSON)
открываются и при сохранении переписываются в TOML.

Каталог с исходниками на Rust (с Cargo.toml) можно указать при
запуске: tvstudio КАТАЛОГ. Если файла проекта .tvsp там нет, среда
создаст проект «программа на Rust» рядом с Cargo.toml и откроет его.

Готовую программу на tvision-rs можно взять в проект: Файл → Импорт
программы. Исходники копируются, строка меню, строка состояния и
команды переходят в {модель приложения:AppModel}. То же из командной
строки: tvs-import ПРОГРАММА.rs КАТАЛОГ ИМЯ.

Проект → Формы из кода находит в исходниках диалоги (Dialog::centered,
Dialog::new и d.add) и добавляет их формами forms/*.tvf: координаты,
надписи, пункты, связи меток, полосы прокрутки, циклы и простые
замыкания вычисляются. Свои виджеты программы и элементы внутри
условий перечисляются в окне сообщений. Код программы при этом не
меняется.

4. Дальше: добавляйте формы (Форма → Новая форма), элементы
({палитра:Palette}), команды и пункты меню ({модель приложения:AppModel}),
а поведение пишите в src/main.rs.

.topic Designer=1000
 Дизайнер форм ▄
  ▀▀▀▀▀▀▀▀▀▀▀▀▀
Окно дизайнера — это и есть будущий диалог или окно: та же рамка,
заголовок, цвет и размер (класс формы — Dialog или Window — выбирается
при создании и в инспекторе). Внутри — настоящие виджеты tvision-rs. Перетащите окно
за заголовок — изменится положение формы, за правый нижний угол — её
размер.

 Мышь
  Щелчок            выбрать элемент
  Ctrl+щелчок       добавить к выделению / убрать из него
  Протяжка          переместить выделенные элементы
  Протяжка за ┘     изменить размер
  Протяжка по полю  выделить рамкой
  Двойной щелчок    свойства элемента
  Правая кнопка     контекстное меню

 Клавиши
  Стрелки           сдвинуть (Ctrl — на 4 клетки)
  Shift+стрелки     изменить размер
  Tab, Shift+Tab    следующий / предыдущий элемент
  Enter             свойства элемента
  Ins               добавить элемент
  Del               удалить
  Esc               снять выделение (свойства формы)
  Ctrl+C, X, V      копировать, вырезать, вставить
  Ctrl+D            дублировать
  Ctrl+Z, Ctrl+Y    отменить, повторить
  Ctrl+A            выделить всё
  Ctrl+PgUp/PgDn    раньше / позже в порядке Tab
  F2                сохранить форму
  Shift+F9          проверить форму (показать диалог)
  F12               перейти к сгенерированному коду формы

Порядок элементов на форме — это порядок перехода по Tab и порядок
полей в структуре данных формы. Форма → Номера Tab показывает его.

Метка (Label) выбирает связанный элемент по горячей букве: свойство
«Связь» — имя элемента. Новая метка сразу связывается с выделенным
элементом.

См. также {Инспектор свойств:Inspector}, {Какой код генерируется:Codegen}.

.topic Inspector=1002
 Инспектор свойств ▄
  ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀
Окно «Инспектор» стоит у правого края: сверху — {компоненты:Palette},
под ними — свойства выделенного элемента верхней формы, а если ничего
не выделено — свойства самой формы. Tab переходит между компонентами
и свойствами.

  Enter, F2       изменить значение (Enter — применить, Esc — отмена)
  Пробел          переключить «да / нет»
  F11             к свойствам; из свойств — вернуться в дизайнер

Значения вводятся одной строкой:
  Текст        ~X~ — горячая буква, \n — новая строка,
               \x03 в начале строки — выровнять по центру
  Пункты       через | : Первый | Второй | Третий
  Команда      cm::OK, cm::CANCEL… или имя своей команды
  Столбцы      таблица: Имя:16 | Телефон:14
  Узлы         дерево: Корень | >Ветка | >>Лист
  Проверка     picture:###-##, range:0..100,
               filter:0123456789, lookup:да|нет
  Цвет формы   серый, синий, бирюзовый

Все свойства сразу (и многострочный текст) — в диалоге свойств:
двойной щелчок по элементу или Enter в дизайнере.

.topic Palette=1003
 Компоненты ▄
  ▀▀▀▀▀▀▀▀▀▀
Список компонентов — верхняя часть окна {«Инспектор»:Inspector}
(Окно → Компоненты). Enter или двойной щелчок добавляет элемент на
верхнюю форму в точку вставки (последний щелчок по пустому месту формы).

  Текст              StaticText — надпись, можно в несколько строк
  Метка              Label — подпись к полю, горячая буква
  Кнопка             Button — посылает команду
  Строка ввода       InputLine, с проверкой и историей
  Флажки             CheckBoxes — значение-маска u32
  Переключатели      RadioButtons — номер выбранного u32
  Список             ListBox — номер выбранного i64
  Многострочное      Memo — текст String
  Поле со списком    InputLine + Combo
  Полоса прокрутки   ScrollBar
  Полоса выполнения  ProgressBar
  Таблица            Table — номер строки с курсором i64
  Дерево             TreeView — узлы с отступами, флажки

Таблица: «Столбцы» — заголовки, через двоеточие ширина (Имя:20);
«Строки» — по строке на запись, ячейки через |; «Правка» разрешает
менять ячейки (F2 или набор текста), «Номера строк», «Сетка».

Дерево: «Узлы» — по строке на узел, вложенность — два пробела отступа
(в инспекторе — знаки >: Документы | >Письма | >>Черновики);
«Раскрыто», «Линии» ветвей, «Флажки» с тремя состояниями.

.topic AppModel=1006
 Модель приложения ▄
  ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀
Проект → Строка меню / Строка состояния / Команды / Параметры.

Команда — константа ui::cmd::ИМЯ с номером и действием:
  ваш код         команду обрабатывает main.rs;
  открыть форму   показать форму модально (forms::имя::run);
  сообщение       показать окно с текстом.

В пункте меню можно сразу написать имя новой команды — она появится в
списке команд. Клавиши записываются как F2, Alt+X, Ctrl+N, Shift+F6.

В строке меню: Пункт, Подменю, Разделитель; ← и → (Ctrl+← / Ctrl+→)
меняют уровень вложенности, Выше / Ниже (Ctrl+↑ / Ctrl+↓) — порядок.

Параметры программы: заголовок, русские надписи стандартных диалогов
и стартовая форма (показывается при запуске).

.topic Codegen
 Какой код генерируется ▄
  ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀
Перед каждой сборкой (и по Проект → Генерировать код) среда пишет:

  src/ui.rs            команды, строка меню, строка состояния,
                       ui::handle_command — действия команд
  src/forms/mod.rs     список форм
  src/forms/имя.rs     форма: ИмяData, ИмяIds, build(), run()
                       (у окна Window — open() и read())

Эти файлы помечены первой строкой «Сгенерировано TV Studio» и
перезаписываются — не правьте их руками. Файл src/main.rs создаётся
один раз и принадлежит вам.

Работа с формой из своего кода:

  let mut data = forms::about::AboutData::default();
  if forms::about::run(app, &mut data) == cm::OK {
      // data.name, data.options… — то, что ввёл пользователь
  }

build() возвращает диалог и id элементов — если нужно что-то
поменять перед показом.

Форма-окно (класс Window) немодальная:

  let id = forms::notes::open(app, &forms::notes::NotesData::default());
  // … позже:
  if let Some(data) = forms::notes::read(app, id) { … }

Класс формы задаётся при создании (Форма → Новая форма) и меняется
свойством «Класс» в инспекторе: Dialog — модальный диалог,
Window — окно на рабочем столе с номером (Alt+1…9); «Растягивается» —
можно менять размер и распахивать.

.topic Editor=1001
 Редактор кода ▄
  ▀▀▀▀▀▀▀▀▀▀▀▀▀
Подсветка Rust, TOML и JSON, номера строк, пометки ошибок последней
сборки (● ошибка, ▲ предупреждение). Строка и столбец курсора
выделены фоном (выключается в Настройки → Параметры среды).

При сохранении файл .rs форматируется программой rustfmt (с учётом
rustfmt.toml проекта и редакции из Cargo.toml). Если в коде
синтаксическая ошибка, файл сохраняется как есть, а сообщение rustfmt
с местом ошибки появляется в окне сообщений. Выключается в Настройки →
Параметры среды; Ctrl+Z отменяет форматирование одним шагом.

  F2           сохранить          Alt+G      перейти к строке
  Ctrl+Z       отменить           Ctrl+L     искать дальше
  Ctrl+Ins     копировать         Shift+Ins  вставить
  Shift+Del    вырезать           Ctrl+Y     удалить строку
  Ctrl+Q F     найти              Ctrl+Q A   заменить
  Ctrl+K B/K   начало / конец блока
  Tab          отступ до кратной 4 позиции

Поиск → Найти в файлах ищет текст во всех файлах проекта; найденное
появляется в {окне сообщений:Messages}.

{Сервер LSP:Lsp} (rust-analyzer для файлов .rs, crates-lsp для
Cargo.toml) добавляет дополнение, переходы и диагностику по мере
набора.

.topic Lsp
 Сервер LSP (rust-analyzer) ▄
  ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀
Пока открыт проект, среда держит запущенными два сервера: языка Rust
(для открытых файлов .rs) и TOML (для Cargo.toml и других файлов
TOML; по умолчанию — crates-lsp). Установка:

  rustup component add rust-analyzer
  cargo install --locked crates-lsp

Другие программы (или полные пути) указываются в Настройки →
Параметры среды; там же серверы выключаются. Пустое поле «Сервер
TOML» — сервер TOML не запускается, rust-analyzer работает как раньше.

В Cargo.toml crates-lsp подсказывает версии и features зависимостей и
помечает устаревшие и несуществующие версии (версии он берёт с
crates.io — нужна сеть). Вместо него в поле «Сервер TOML» можно указать
taplo («taplo lsp stdio») — проверку синтаксиса и ключей TOML.

  Ctrl+Space   дополнение (само — после «.» и «::»; в .toml — после «.»
               и после «= "» — версии пакета)
               ↑↓ PgUp PgDn — выбор, Enter/Tab — вставить, Esc — закрыть
  F12          перейти к определению
  Alt+←        вернуться назад
  Shift+F12    найти все ссылки — список в окне сообщений

Диагностика обновляется через долю секунды после набора: строки
помечаются на полосе номеров (● ошибка, ▲ предупреждение), места —
цветным фоном в тексте, сообщение строки под курсором — в строке
состояния. Поиск → Диагностика LSP — все замечания списком.

Ход индексации и имена запущенных серверов видны в заголовке окна
сообщений. Если сервер завершился, Поиск → Перезапустить сервер LSP
(перезапускаются оба).

.topic Build=1007
 Сборка и запуск ▄
  ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀
  Alt+F9    cargo check      F9   cargo build
  Ctrl+F9   собрать и запустить программу

Перед сборкой среда сохраняет файлы (Настройки → Параметры среды) и
генерирует код. cargo работает в фоне — среда не замирает; вывод
идёт в {окно сообщений:Messages}. Сборка → Остановить прерывает её.

При запуске экран отдаётся программе; после её выхода нажмите Enter.

F8 / Shift+F8 — следующая / предыдущая ошибка.

.topic ProjectTree=1004
